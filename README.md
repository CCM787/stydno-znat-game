# Стыдно знать — домашняя версия

Локальная игра на четыре устройства: большой экран для всех, ваш телефон как пульт,
два телефона игроков. Всё крутится на вашем компьютере, интернет не нужен —
достаточно общего Wi-Fi.

Пет-проект: React + TypeScript на фронтенде, Node.js без зависимостей на бэкенде,
обновления в реальном времени через Server-Sent Events. Разработан с помощью
[Claude Code](https://claude.com/claude-code) — архитектура и решения мои, код писался
агентом по задачам и проходил ревью. В репозитории — демо-набор вопросов (`packs/demo.json`).

## Запуск

1. Поставьте Node.js 22.5 или новее (банк вопросов хранится во встроенном `node:sqlite`) — https://nodejs.org
2. Откройте папку в терминале (в VS Code: `Терминал → Новый терминал`) и выполните:

   ```
   cd frontend && npm install && npm run build && cd ..
   node server.js
   ```

   Первая строка собирает фронтенд (React) в `public/` — нужна один раз и заново
   после любых правок во `frontend/`. На Windows можно просто дважды кликнуть
   `start.bat`, на Mac — `start.command`: они сами пересобирают фронтенд перед
   запуском сервера.

3. В консоли появятся три адреса:

   ```
   Экран (этот компьютер):   http://localhost:3000/screen
   Пульт ведущего (телефон): http://192.168.х.х:3000/host
   Игроки (телефоны):        http://192.168.х.х:3000/player
   ```

Экран открывайте на мониторе или телевизоре в полноэкранном режиме (F11).
Игрокам ссылку диктовать не надо — на экране висит QR-код.

Если телефоны не открывают адрес: Windows при первом запуске спрашивает разрешение
для Node.js в сети — нужно разрешить для **частных сетей**. И проверьте, что телефон
не сидит в гостевом Wi-Fi — гостевая сеть изолирует устройства друг от друга.

## Как это устроено

Бэкенд — один процесс Node.js без единой зависимости, только стандартная библиотека.
Фронтенд — React (TypeScript) на Vite, собирается в статику и раздаётся тем же
сервером: `server.js` ничего не знает о том, что `public/` теперь собранный SPA,
а не набор голых HTML-файлов.

- **`server.js`** — HTTP-сервер: раздаёт статику из `public/` (включая собранный
  фронтенд), хранит состояние игры в памяти, принимает действия и рассылает
  состояние всем устройствам. Любой путь, не совпавший с файлом сборки или
  `/api/*`, отдаёт `index.html` — маршрутизацию между экранами решает
  `react-router` на клиенте.
- **`frontend/`** — исходники React-приложения (`npm run dev` — разработка с
  HMR, проксирует `/api` и `/images` на `localhost:3000`; `npm run build` —
  прод-сборка прямо в `../public`). Собранные файлы не хранятся в git.
- **Состояние живёт только на сервере.** Клиенты ничего не решают: игрок отправляет
  «нажал» или «выбрал Б», сервер ставит метку времени по своим часам и решает,
  кто был первым. Поэтому разные телефоны и разные лаги не ломают справедливость.
- **Рассылка — Server-Sent Events** (`GET /api/stream`). Это односторонний поток
  от сервера к браузеру, встроен в браузер, не требует библиотек и переживает
  разрыв связи сам. WebSocket здесь не нужен: обратный канал — обычный POST.
- **Действия — POST `/api/action`** с полем `action`: `join`, `answer`, `buzz`
  у игроков; `newGame`, `ask`, `reveal`, `correct`, `wrong`, `adjust`, `next`,
  `setDrawer`, `timer`, `endGame` у ведущего.
- **Правильный ответ не уходит на клиент**, пока вы его не показали. Пульт получает
  вопрос целиком, экран и игроки — без поля с ответом. Заглянуть в код страницы
  и подсмотреть не выйдет.
- **Кто есть кто.** Браузер при первом заходе генерирует токен и кладёт в
  `localStorage`. Токен привязывается к месту (Игрок 1 / Игрок 2), поэтому
  перезагрузка страницы или заблокированный экран не теряют место и счёт.
- **Рисование** — координаты нормализованы (0..1), линия шлётся кусками каждые 90 мс
  на `POST /api/draw` и сразу транслируется на экран. Поэтому рисунок появляется
  на телевизоре в реальном времени, а не после отрыва пальца.

Экраны — маршруты React-приложения: `/screen` (общий экран), `/player` (телефон игрока),
`/host` (пульт ведущего), `/builder` (редактор вопросов), `/login`.

**Безопасность.** Вход ведущего — форма пароля; сервер сверяет его за постоянное время
и выдаёт случайный сессионный токен в HttpOnly-куке (сам пароль в куку не попадает,
перезапуск сервера сбрасывает сессии). Статика и картинки раздаются только изнутри своих
папок: пути вида `/images/..%2F...` отклоняются.

## Ход игры

1. На пульте: **Новая игра** → выбираете пакет вопросов, вписываете имена → **Начать игру**.
2. Игроки заходят по QR и занимают места. Занятое место второй раз занять нельзя;
   если кто-то сел не туда — **Освободить место** на пульте.
3. **Открыть вопрос** — вопрос появляется на экране, включается замер времени.
4. Дальше по типу тура:
   - **Тур 1, четыре варианта.** Оба игрока жмут вариант на своём телефоне.
     На экране под вопросом видно, кто нажал первым и сколько миллисекунд, но не что выбрал.
     Вы жмёте **Показать ответ** — экран раскрывает правильный вариант и чужие выборы.
     Балл начисляете кнопкой **Балл {имя}**.
   - **Тур 2, на скорость.** У игроков одна большая кнопка. Первый нажавший
     заливает экран своим цветом — имя и время реакции. **Балл** или **Мимо**:
     после «Мимо» баззер снова открывается для второго.
   - **Тур 3, рисование.** Выбираете на пульте, кто рисует. У рисующего появляется
     холст и слово (его видите только вы и он), у второго — кнопка «Я знаю».
     Рисунок идёт на большой экран. Есть таймер на 60 секунд и «Стереть холст».
5. **Дальше →** переводит на следующий вопрос, в конце тура — сам переходит в следующий.
6. Счёт можно править вручную кнопками − и + рядом с именем.
7. **Завершить игру** сохраняет лог. Начать новую игру с другой парой можно сразу,
   ничего не перезапуская.

## Вопросы

Лежат в папке `packs/` — по файлу на игру. Правятся в любом текстовом редакторе.
Файл перечитывается при каждом старте игры, перезапускать сервер не нужно.

```json
{
  "name": "Игра 1",
  "rounds": [
    {
      "title": "Тур 1. Четыре варианта",
      "questions": [
        {
          "type": "choice",
          "text": "Текст вопроса",
          "image": "/images/картинка.jpg",
          "options": ["А", "Б", "В", "Г"],
          "correct": 0,
          "points": 1
        }
      ]
    },
    {
      "title": "Тур 2. На скорость",
      "questions": [
        { "type": "buzz", "text": "Текст вопроса", "answer": "Ответ для ведущего", "points": 1 }
      ]
    },
    {
      "title": "Тур 3. Рисование",
      "questions": [
        { "type": "draw", "text": "Рисуем и угадываем", "word": "Слово", "points": 1 }
      ]
    }
  ]
}
```

- `correct` — номер правильного варианта, считая с нуля.
- `image` — необязательно; файл кладите в папку `images/`, путь пишите `/images/имя.jpg`.
- `points` — сколько даёт кнопка «Балл», по умолчанию 1.
- `note` — заметка, которую видите только вы на пульте.

Туров может быть сколько угодно, типы вопросов можно смешивать внутри тура.

## Логи

После каждого вопроса и при завершении игры в `logs/` пишутся два файла:
`.json` для разбора и `.txt` для чтения — вопрос, что выбрал каждый игрок,
время реакции, кому ушёл балл, итоговый счёт.

## Свой сервер и свой домен

Бэкенд — обычный Node-процесс без зависимостей, но перед первым запуском (и после
каждого `git pull` с изменениями во `frontend/`) нужно собрать фронтенд:
`cd frontend && npm ci && npm run build`. `.github/workflows/deploy.yml` делает
это автоматически при деплое.

Две переменные окружения делают приложение пригодным для публичного хостинга:

```
PUBLIC_URL=https://igra.example.com   # ссылка и QR на экране — по домену, а не по локальному IP
HOST_KEY=длинная-случайная-строка     # пароль для входа на /host и /builder
PORT=3000
```

Без `HOST_KEY` пульт ведущего доступен любому, кто знает адрес: он раздаёт очки и видит
правильные ответы. В локальной сети это нормально, в интернете — нет. Если `HOST_KEY` задан,
при заходе на `/host` или `/builder` без активной сессии показывается форма — пароль вводится
один раз на устройство, дальше браузер сам держит вход (HttpOnly-кука со случайным токеном сессии на полгода; после перезапуска сервера войти нужно заново). Ключ
придумывайте длинный и не показывайте его на экране, когда игроки смотрят.

Запуск под systemd:

```ini
[Unit]
Description=Стыдно знать
After=network.target

[Service]
WorkingDirectory=/opt/stydno-znat
ExecStart=/usr/bin/node server.js
Environment=PORT=3000
Environment=PUBLIC_URL=https://igra.example.com
Environment=HOST_KEY=замените-на-свою-строку
Restart=always
User=www-data

[Install]
WantedBy=multi-user.target
```

nginx перед ним. Важны две строчки про буферизацию: состояние игры едет через
Server-Sent Events, и при включённом буфере nginx придержит поток — экран замрёт,
а баззер начнёт врать.

```nginx
server {
    server_name igra.example.com;

    location / {
        proxy_pass http://127.0.0.1:3000;
        proxy_http_version 1.1;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;

        proxy_buffering off;          # без этого SSE не работает
        proxy_cache off;
        proxy_read_timeout 1h;        # поток живёт всю игру
    }
}
```

Сертификат — `certbot --nginx -d igra.example.com`. HTTPS тут не роскошь: без него
браузер на телефоне может резать часть возможностей страницы.

Что учесть при игре через интернет:

- **Состояние живёт в памяти одного процесса.** Перезапуск сервиса обнуляет игру
  (логи завершённых игр при этом остаются на диске). Несколько воркеров или балансировщик
  на два инстанса не заработают — нужен ровно один процесс.
- **Замер скорости станет честнее, но грубее.** Сервер по-прежнему ставит метки времени сам,
  так что подкрутить их с телефона нельзя, но к реакции игрока добавится пинг до сервера.
  У всех он разный, и на баззере разница в 50–100 мс уже заметна. Для одной комнаты
  локальная сеть честнее.
- **Одна игра на весь сервер.** Комнат нет: кто угодно, открывший `/player`, займёт
  свободный слот в вашей игре.
